# Dooray 연동 기술노트 — 라이선스 없이 봇 만들기

> 연합인포맥스 AI부 · 2026-09-03
> 이 문서의 모든 내용은 **실제로 돌려보고 확인한 것**이다. 문서에만 있고
> 확인하지 못한 것은 그렇다고 밝혔다.

---

## 0. 왜 이 문서가 필요했나

Dooray의 공식 **Extension Agent**는 AI 프리미엄 라이선스가 있어야 쓸 수 있다.
라이선스 발급 없이 같은 일을 할 수 있는지 확인해 봤고, **결론은 된다**.

핵심은 하나다.

> Dooray 소켓 모드의 인증은 **에이전트 단위가 아니라 사람(멤버) 단위**다.
> 개인 액세스 토큰으로 소켓을 열 수 있고, 그 순간부터 그 계정이 보는 모든
> 대화가 흘러들어온다.

`python-dooray-sdk`를 뜯어보고 알아낸 것과, 직접 구현하며 막혔던 것을 아래에
정리한다. SDK를 그대로 쓰지 않고 자체 클라이언트를 만든 이유도 나온다
(§1.3, §1.4가 SDK의 실제 결함이다).

## 1. 소켓 모드 — 메시지 받기

### 1.1 연결 절차

```
POST https://api.dooray.com/common/v1/socket-mode/tokens
     Authorization: dooray-api {개인 액세스 토큰}
     {}                                       ← 본문은 빈 객체

→ result: { accessToken, tenantId, organizationMemberId }
```

받은 값으로 WebSocket을 연다.

```
wss://{테넌트도메인}/messenger/v5/ws/{tenantId}/{organizationMemberId}
     Authorization: Bearer {accessToken}
```

`organizationMemberId`는 **내 멤버 ID**다. 뒤에서 계속 쓰인다(§3).

### 1.2 토큰 수명 — 만료 전에 스스로 끊어야 한다

`accessToken`은 JWT이고 수명이 **약 1시간**이다. SDK는 연결이 끊긴 뒤에야
재발급하는데, 그러면 만료 순간부터 재연결까지 **메시지를 놓친다**.

JWT의 `exp`를 직접 읽어 만료 2분 전에 우리가 먼저 끊고 재발급했다.

```python
payload = accessToken.split(".")[1]
payload += "=" * (-len(payload) % 4)          # base64 패딩 복원
exp = json.loads(base64.urlsafe_b64decode(payload))["exp"]
ttl = max(exp - time.time() - 120, 60)
```

30초마다 `{"type":"ping"}`을 보내 연결을 유지한다.

### 1.3 ⚠️ macOS에서는 certifi가 필수

WebSocket 핸드셰이크가 이렇게 죽는다.

```
CERTIFICATE_VERIFY_FAILED: unable to get local issuer certificate
```

macOS 시스템 CA 스토어가 불완전해서다. `websocket-client`에 CA 번들을 명시해야
한다. **SDK도 이걸 빠뜨려 같은 자리에서 실패한다.**

```python
ws.run_forever(sslopt={"ca_certs": certifi.where()})
```

같은 이유로 `urllib`은 사내망에서 쓰지 말 것 — Fortinet TLS 가로채기 때문에
`self signed certificate in certificate chain`이 난다. `requests`(내부적으로
certifi 사용)를 쓰면 통과한다.

### 1.4 ⚠️ 1008 — 한 토큰에 소켓 하나

같은 토큰으로 두 번째 소켓을 열면 먼저 것이 끊기거나 이쪽이 거절당한다.

```
closed code=1008 reason=AGENT_ALREADY_CONNECTED
```

**재연결 간격을 종료 사유별로 달리해야 한다.** 이걸 구분하지 않으면 1008을
맞고 즉시 재시도하는 뜨거운 루프에 빠진다(우리가 실제로 겪었다).

| 종료 사유 | 재연결 |
|---|---|
| 토큰 갱신(계획된 종료) | 즉시 |
| `1008` 중복 접속 | **15초 대기** |
| 그 외 | 지수 백오프 |

### 1.5 프레임 구조

```json
{
  "type": "channelLog",
  "content": {
    "channelId": "...",
    "senderId": "...",
    "id": "메시지 ID",
    "type": 0,
    "text": "본문",
    "token": "UUID"
  }
}
```

`content.type` 실측값:

| 값 | 뜻 | 처리 |
|---|---|---|
| 0 | 일반 메시지 | ✅ |
| 1 | 시스템 (봇 초대·퇴장 등) | 무시 |
| 2 | 봇 알림 (Dooray! News) | 별도 처리 (§3) |
| 4 | 파일 첨부 | ✅ `content.file` |
| 10 | 답글 | ✅ 아래 주의 |

**답글(10)은 `text`가 JSON 문자열로 이중 인코딩되어 있다.** 한 겹 벗겨야 한다.

```python
if content["type"] == 10:
    text = json.loads(content["text"])["text"]
```

원본 메시지는 `references.originalLogMap`에 통째로 동봉된다.

### 1.6 ⚠️ 루프 방지 — 내가 보낸 걸 내가 받는다

개인 계정 소켓이라 **내가 API로 보낸 응답도 나에게 되돌아온다.** 그대로 두면
무한 루프다. 그렇다고 `senderId == 나`로 걸러 버리면 **내가 친 명령도 못 받는다.**

구분 기준은 `content.token`이다.

```
사람이 앱에서 친 메시지  →  content.token 있음 (UUID)
우리가 API로 보낸 메시지  →  content.token 없음
```

```python
if sender == my_member_id and "token" not in content:
    return          # 우리가 보낸 응답 — 폐기
```

### 1.7 ⚠️ 화이트리스트가 필수다

소켓에는 **초대 개념이 없다.** 그 계정이 참여 중인 **모든 대화방**이 흘러들어온다
(우리 계정은 250개). 처리할 채널을 명시적으로 지정해야 한다.

```
DOORAY_ROUTES="3267267775953625054:crm,4412501746823008358:support"
```

이 키 집합이 곧 화이트리스트다. 없는 채널의 메시지는 **본문을 로그에 남기지도
않고** 버린다.

## 2. 메시지 보내기

```
POST /messenger/v1/channels/{channelId}/logs
     { "text": "...", "attachments": [...] }        → 일반 발신

POST /messenger/v1/channels/{channelId}/logs/{messageId}/reply
     { "text": "..." }                              → 인용 답장

GET  /messenger/v1/channels                         → 참여 중인 채널 목록
GET  /messenger/v1/channels/{channelId}/logs?size=N → 최근 메시지
```

### 유용한 부수 효과

`GET /channels` 응답의 각 채널에 **내 멤버 ID가 들어 있다.**

```json
"me": { "member": { "organizationMemberId": "3267267451433100066" } }
```

덕분에 소켓 토큰을 새로 발급하지 않고도 내 ID를 알 수 있다. 소켓을 쓰지 않는
프로세스(커맨드 서버)에서 유용하다.

`users.participants`로 1:1 상대도 알 수 있어, 채널 목록 **1회 호출**로
`{상대 memberId: 1:1 채널 ID}` 지도를 만들 수 있다.

### ⚠️ 마크다운은 거의 안 먹는다

표(`|---|`), **굵게**, ~~취소선~~ 전부 렌더링되지 않는다. **인라인 코드만**
동작한다. 서식이 필요하면 `attachments`를 써야 한다.

## 3. Dooray! News — 개인 알림함

News는 **개인 봇 채널**이고, 놀랍게도 **채널 ID가 그 사람의 memberId와 같다.**
일반 대화방 목록(`GET /channels`)에는 나오지 않는다.

```
content.channelId == 내 organizationMemberId   →  이 프레임은 News
```

### 무엇이 되고 무엇이 안 되나

| | 결과 |
|---|---|
| 내 News로 발신 | ✅ 200 |
| **남의 News로 발신** | ❌ 500 `CHANNEL_NOT_JOINED_MEMBER_ERROR` |
| 남과의 1:1 대화방으로 발신 | ✅ 200 |

**남의 News에 못 쓰는 건 그 채널의 멤버가 아니기 때문이다.** Dooray-Bot이 모두의
News에 쓰는 것은 시스템 봇 권한이라 개인 토큰으로는 흉내 낼 수 없다. 우회로가
아니라 권한의 벽이다.

→ 그래서 우리는 **본인이면 News, 남이면 1:1 대화방**으로 갈라 보낸다.

### News 알림 프레임 파싱

```
content.customName = "Dooray-Bot"
content.type       = 2
content.attachments[0].title     = "프로젝트코드/번호: 제목"
content.attachments[0].titleLink = "https://.../project/tasks/{업무ID}"
```

⚠️ `action`이 `create`가 아니라 **`update`인 프레임에만 attachments가 채워진다.**

⚠️ News에는 **참여 중인 전 프로젝트의 알림**이 흘러든다. 프로젝트 코드로 먼저
걸러내지 않으면 매번 남의 프로젝트에 조회를 날려 403을 맞는다.

## 4. Dooray 알림 규칙 — 실측표

기획서는 "완료되면 알림이 간다"를 전제하고 있었는데, 실제로는 그렇지 않다.
여러 조합을 만들어 확인한 결과다.

| 사건 | 알림 |
|---|---|
| 업무 **등록** | ✅ 간다 |
| 담당자·참조자 **추가** | ✅ 간다 |
| **상태 변경** (접수 → 완료) | ❌ **안 간다** |
| 내가 한 행동 | ❌ 나에게는 안 온다 |
| 내가 **작성자**인 업무 | ❌ 나에게는 안 온다 |

여기에 더해:

> ⚠️ **작성자는 참조자가 될 수 없다.** 봇이 작성자인 구조에서 요청자를 참조자로
> 넣으면 `users.cc`가 **빈 배열**로 돌아온다. 조용히 무시된다.

### 그래서 완료 감지는 폴링이다

상태 변경에 알림이 없으므로 **우리가 물어봐야 한다.** 스냅샷 비교 방식이라
주기는 **지연 시간만 결정하고 누락 여부는 결정하지 않는다.**

```python
newly_closed = {id for id, state in now.items()
                if state == "closed" and prev.get(id) != "closed"}
```

⚠️ 생성 직후 첫 폴링 전에 완료되면 "처음 보는데 이미 완료"로 판단해 통보가
누락된다. 티켓을 만든 즉시 스냅샷에 등록해 두어야 한다.

## 5. 슬래시 커맨드 — 버튼을 쓰려면

### 5.1 등록 경로 (찾기 어려웠다)

**Dooray! 메신저 → 좌측 상단 내 이름 → 슬래시 커맨드 연동**
(`https://{테넌트}/messenger/integration`)

개인 설정이나 관리자 화면이 **아니다.** 메신저 안에 있다.

```
앱 만들기 → 토큰 발급 → Interactive Message 체크 → 커맨드 추가
                                                  → 대화방에 커맨드 추가
```

**대화방에 추가하는 단계를 빠뜨리면 커맨드가 보이지 않는다.**

### 5.2 두 개의 URL이 모두 필요하다

| 항목 | 받는 것 |
|---|---|
| **Request URL** | `/커맨드` 입력 |
| **Interactive Message Request URL** | **버튼 클릭** |

뒤엣것을 비우면 목록은 떠도 **버튼이 먹통**이 된다.

### 5.3 토큰 두 개를 헷갈리지 말 것

커맨드 요청 페이로드:

```json
{
  "channelId": "...", "userId": "...", "command": "/처리", "text": "",
  "responseUrl": "https://{테넌트}/messenger/api/commands/hook/{cmdToken}",
  "appToken": "앱 토큰 — 요청이 진짜인지 검증용",
  "cmdToken": "이번 호출에만 유효한 토큰"
}
```

- **`appToken`** — 앱 설정 화면에서 볼 수 있는 고정값. **요청 검증에만** 쓴다.
- **`cmdToken`** — **호출마다 새로 발급**된다. `responseUrl`에 이미 박혀 있다.

`appToken`으로 hook URL을 만들어 쏘면 이렇게 거절당한다.

```
INTEGRATION_COMMAND_CALL_NOT_EXIST_ERROR
```

### 5.4 responseUrl — 봇 이름으로 임의 시점 발신

`responseUrl`로 POST하면 **앱 이름(= 봇)으로** 메시지를 보낼 수 있다.

```
POST {responseUrl}
{ "channelId": "...", "responseType": "inChannel", "text": "...", "attachments": [...] }
```

**다만 그 호출 맥락 안에서만이다.** 아무 때나 먼저 말을 거는 자유 발신 봇은
개인 토큰으로 만들 수 없다. 버튼 클릭도 하나의 호출이므로, **클릭 시점에는
봇으로 말할 수 있다.**

### 5.5 응답 형태

| 필드 | 값 |
|---|---|
| `responseType` | `ephemeral` 누른 사람만 / `inChannel` 방 전체 |
| `replaceOriginal: true` | 그 자리에서 내용만 교체, **알림 없음** |
| `deleteOriginal: true` | 지우고 새로 전송, **알림 감** |

### 5.6 ⚠️ 두 가지 결정적 제약

실측으로 확인한 것이고, 설계를 바꿔야 했던 지점이다.

**① 일반 메시지의 버튼은 클릭이 전달되지 않는다.**

메신저 API로 보낸 메시지에 `actions`를 넣으면 **버튼이 그려지긴 한다.** 그런데
눌러도 아무 일도 일어나지 않는다. 진짜 업무를 바꾸는 값을 실어 눌러도 상태가
그대로였다. 개인 토큰으로 보낸 메시지의 버튼이 **어느 앱 것인지 Dooray가 알
방법이 없기** 때문이다.

> **버튼이 실제로 동작하는 곳은 슬래시 커맨드 응답뿐이다.**

**② 슬래시 커맨드에 여러 줄을 실을 수 없다.**

`/커맨드` 뒤에 Shift+Enter로 개행하면 **커맨드로 인식되지 않고 일반 메시지로**
전송된다. 여러 줄 양식을 커맨드 인자로 넘길 수 없다는 뜻이다.

**우회** — 양식은 일반 메시지로 올리고, 커맨드가 `GET /channels/{id}/logs`로
**방의 로그에서 그 사람의 마지막 양식을 찾아 읽는다.** 커맨드 응답이므로 버튼이
동작한다.

## 6. 업무(Project) API

```
GET  /project/v1/projects/{id}/workflows
GET  /project/v1/projects/{id}/posts?size=100
GET  /project/v1/projects/{id}/posts/{postId}
POST /project/v1/projects/{id}/posts
POST /project/v1/projects/{id}/posts/{postId}/set-workflow
PUT  /project/v1/projects/{id}/posts/{postId}          ← 본문 수정
```

### 목록 응답에 필요한 게 다 들어 있다

`GET /posts` 한 건에 `id · number · subject · workflowClass`가 모두 있다.
**건별 상세 조회(N+1)를 할 이유가 없다.** 우리도 처음에 목록 + 건별 조회를
하다가 걷어냈다 — 목록 1회로 끝나니 응답이 눈에 띄게 빨라졌다(0.6초).

### 워크플로는 이름이 아니라 class로 찾아야 한다

상태 이름은 프로젝트마다 다르다(`할 일`/`등록`, `진행 중`/`진행`).
`class` 값(`registered` / `working` / `closed`)으로 찾는다.

### 삭제 API는 없다

`DELETE /posts/{postId}` → **404**. 화면에서 지워야 한다.

### 업무에는 임의 필드를 붙일 수 없다

완료 알림을 받았을 때 "어느 대화방 어느 메시지에 답할지"를 알아야 하는데
담을 필드가 없다. **본문에 한 줄로 남겼다.**

```
[요청출처] channel={채널ID} message={메시지ID} requester={요청자ID}
```

같은 방식으로 중복 통보 방지 표식도 본문에 남긴다(`[통보완료]`). 두 프로세스가
다른 기계에서 도는 탓에 상태를 나눌 매체가 업무 본문뿐이었다.

## 7. 인바운드 — Dooray가 우리를 호출한다

소켓은 **아웃바운드**다. 우리가 붙는다. 그런데 슬래시 커맨드와 버튼은 **Dooray가
우리 서버를 호출**한다. 공개 접근 가능한 HTTPS URL이 필요하다.

### ⚠️ ngrok은 사내망에서 안 된다

Fortinet TLS 가로채기 때문에 터널 자체가 HTTP 403으로 막힌다.

```
issuer=CN=FG6H1FTB25900086, O=Fortinet
```

터널에 도달한 요청이 **0건**이었다.

### 사내 서버 + Traefik으로 해결

`ai-node`에 공인 IP와 Traefik, Let's Encrypt, `*.infomaxai.com` 와일드카드 DNS가
이미 있었다. 새 서버도 DNS 작업도 필요 없었다.

⚠️ **Traefik v3.1에서 Swarm 프로바이더가 분리되며 라벨 이름이 바뀌었다.**

```
traefik.docker.network   →   traefik.swarm.network
```

옛 이름을 쓰면 Traefik이 컨테이너 IP를 못 골라 라우터를 등록하지 않고,
**기본 자체서명 인증서**를 내민다. `curl: (60) self-signed certificate`가
이것 때문이다.

⚠️ 이미지를 레지스트리 없이 로컬 빌드로 쓰면 **그 노드에 고정**해야 한다.
아니면 다른 노드에 배치돼 `No such image`로 죽는다.

```yaml
deploy:
  placement:
    constraints: [node.hostname == ai-node-1]
```

## 8. 요약 — 라이선스 없이 되는 것과 안 되는 것

### 되는 것

| | |
|---|---|
| 메시지 수신 | 소켓 모드 (아웃바운드) |
| 메시지 발신·인용 답장 | 메신저 API |
| 업무 등록·상태 변경·본문 수정 | Project API |
| 슬래시 커맨드 + **버튼** | 연동 서비스 앱 |
| 봇 이름으로 발신 | responseUrl (호출 맥락 안에서) |
| 내 Dooray! News 알림 | 채널 ID == 내 memberId |
| 남에게 개인 알림 | 1:1 대화방 |

### 안 되는 것

| | 이유 |
|---|---|
| **남의 Dooray! News에 쓰기** | 그 채널의 멤버가 아님. 시스템 봇 권한 필요 |
| 아무 때나 먼저 말 거는 봇 | `cmdToken`이 호출마다 발급됨 |
| 일반 메시지의 버튼 클릭 | 어느 앱 것인지 Dooray가 모름 |
| 여러 줄 슬래시 커맨드 | 개행이 들어가면 일반 메시지가 됨 |
| 상태 변경 자동 알림 | Dooray가 보내지 않음 → 폴링으로 대체 |

**라이선스 없이 못 넘은 벽은 사실상 첫 줄 하나뿐이고, 그마저 1:1 대화방으로
대체된다.**

## 10. 다음에 이걸 하는 사람에게

1. **소켓부터 열어 보라.** 개인 액세스 토큰 하나로 5분이면 된다. 여기가 되면
   나머지는 다 된다.
2. **`content.token`을 먼저 이해하라.** 루프 방지의 핵심이고, 모르면 무한
   루프를 겪고 나서야 알게 된다.
3. **화이트리스트를 먼저 걸어라.** 안 그러면 전 대화방이 로그에 쏟아진다.
4. **버튼이 필요하면 처음부터 슬래시 커맨드로 설계하라.** 일반 메시지에
   버튼을 달았다가 갈아엎게 된다.
5. **알림을 기대하지 마라.** 상태 변경에는 알림이 없다. 폴링이거나, 버튼으로
   바꿔서 클릭을 곧 이벤트로 삼거나 둘 중 하나다.
