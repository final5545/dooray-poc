## 1. 한 줄 요약

**AI 프리미엄 라이선스 없이 양방향 봇이 실제로 동작한다.**
CRM 조회와 기술지원 요청 자동화 두 기획서의 핵심 흐름을 모두 구현·검증했다.

```
영업담당자가 대화방에 요청
  → 규칙 기반 추출 + Claude 보강
  → CRM 조회
  → Dooray 업무(현황판)에 티켓 자동 등록
  → 접수 확인 회신
  → 기술담당자가 완료 처리
  → 폴링이 감지
  → 원 요청 메시지에 인용 답장으로 완료 통보
```

실제 대화방 기록:
```
15:00:22  비엔케이자산운용 / E21016 단말기 노후교체 요청드립니다. / 희망일정 : 9월 10일(목) 오전 중
15:00:25  기술지원 요청이 접수되었습니다. / 비엔케이자산운용 노후교체 [접수 9/10] / 고객번호 : E21016
15:18:43  ✅ 기술지원 요청이 처리 완료되었습니다. / 비엔케이자산운용 노후교체    ← 원 요청에 인용 답장
```

## 2. 전략 — 왜 자체 구현인가

### 블로커

`infomax.dooray.com` 서브서비스에 **AI 스튜디오 메뉴가 없다**(2026-09-02 확인).
익스텐션 에이전트를 만들 수 없으니 에이전트 토큰도 없다.

### 우회

SDK 소스 분석에서 Socket Mode 인증이 에이전트 전용이 아님을 확인했다(`02` §2).
**설정 > API > 개인 액세스 토큰**(계정당 10개, 라이선스 무관)으로 동일 엔드포인트를
호출해 실제 연결에 성공했다.

배부장님 결정으로 이 방식으로 진행 중이며, 리스크는 §7에 정리했다.

### 정식 방식과의 차이

| | 익스텐션 에이전트 | 현행 자체 구현 |
|---|---|---|
| 라이선스 | 필요 | 불필요 |
| 정체성 | 봇 (별도 계정) | **사용자 본인** |
| 수신 범위 | 초대된 대화방만 | **참여 중인 모든 대화방** |
| 발신·작성 표시 | 봇 이름 | **본인 이름** |
| 토큰 권한 | 봇 범위 | **본인과 동일 (메일·드라이브 포함)** |

## 3. 구현 현황

```
crm/          고객정보 조회        303줄
  parser      E-code 추출 (E+5~6자리, 복수 지원)
  masking     이메일·전화 마스킹 (PoC에선 OFF)
  formatter   기획서 §5 출력 형식
  client      저장소 인터페이스 + Fake/Http
  service     진입점

support/      기술지원 자동화      961줄
  extractor   요청유형·고객번호·희망일 규칙 기반 추출
  llm         LLM 보강 계층 (프롬프트·응답 파싱)
  llm_anthropic  Claude Haiku 4.5 어댑터 (회로 차단기 포함)
  ticket      제목·본문 조립 + 원 요청 좌표
  repository  Dooray 업무 API 어댑터
  service     진입점
  watcher     완료 감지 폴링 (스냅샷 비교)
  completion  완료 판정 → 회신 지시
  notify      Dooray! News 프레임 파싱

routing.py    채널 → 핸들러 라우팅   51줄
standalone/   에이전트 + 실측 프로브 401줄 + 프로브 9종

tests/        153개 전부 통과
```

### 설계 원칙

**Dooray와 비즈니스 로직을 분리했다.** `crm/`과 `support/`는 Dooray를 모르고,
전부 Fake 저장소로 단위테스트된다. `agent.py`는 조립만 한다.

**조기 반환이 개인정보 대응의 1차 방어선이다.** 대화방 전체 메시지가 유입되므로
처리 대상이 아니면 본문을 남기지 않고 폐기한다. "무관한 메시지는 반드시 None"이
테스트로 고정되어 있다.

**라우팅 테이블이 곧 화이트리스트다.** `DOORAY_ROUTES`에 없는 채널은 통째로 버린다.

## 5. 실측으로 확정된 Dooray 동작

> 상세는 `06-자체구현-레퍼런스.md`. 여기는 설계에 영향을 준 것만.

### 5.1 🔴 알림 규칙

하루를 들여 확인한 결과, Dooray 알림은 이렇게 동작한다.

| 이벤트 | 알림 |
|---|---|
| 업무 **등록** | ✅ |
| 참조자·담당자 **추가** | ✅ |
| 상태 **변경**(완료 등) | ❌ |
| **자기 행동** | ❌ |
| **자기가 작성자인 업무** | ❌ |

마지막 두 줄이 결정적이다. **봇이 티켓을 만들므로 봇은 항상 작성자이고,
따라서 자기 티켓에 대한 알림을 영원히 받지 못한다.**

푸시 경로(웹훅·자동화·News·참조자)를 전부 확인했으나 봇 계정 하나로는 막혀 있다.
→ **완료 감지는 폴링으로 확정.**

### 5.2 Dooray! News

- **개인 봇 채널**이며 **채널 ID가 자기 `memberId`와 같다**
- 일반 대화방 목록(`/messenger/v1/channels`)에 나오지 않는다
- 우리 소켓으로 **실시간 수신된다** (실측 확인)
- `content.type = 2`, `customName = "Dooray-Bot"`
- 업무 정보는 `attachments[0]`의 `title` / `titleLink`에 들어 있다
- ⚠️ `attachments`는 `create`가 아니라 뒤따르는 **`update`** 프레임에 채워진다

봇 계정이 생겨 작성자가 분리되면 이 경로로 푸시 전환이 가능하다.
파싱 코드(`support/notify.py`)는 이미 만들어 두었다.

### 5.3 메시지 표현 범위

마크다운은 **인라인 코드만** 렌더링된다. 표·굵게·취소선 모두 미지원.
개행은 정상. → 카드는 개행 + 유니코드 괘선 + 이모지로 조립.

### 5.4 기타

- 업무(Project)·위키 REST API 정상 동작 — SDK 미문서화와 무관
- 워크플로 `class`: `registered` / `working` / `closed` (이름은 프로젝트별 커스텀)
- 토큰당 활성 소켓 1개 (`1008`) — 개인 토큰에도 적용
- 소켓 토큰(JWT) 수명 1시간

## 6. 완료 통보 설계

Dooray가 상태 변경 알림을 주지 않으므로 폴링한다.

```
목록 API 1회 호출 → {업무ID: workflowClass} → 직전 스냅샷과 비교
```

| 성질 | 내용 |
|---|---|
| 주기 | 300초 (환경변수) |
| 비용 | 호출 1회. 티켓이 몇 건이든 동일 |
| 누락 | **없음** — 스냅샷 비교라 프로세스가 죽었다 살아나도 이어진다 |
| 중복 | 없음 — 완료 전이만 1회 통보 |
| 첫 실행 | 통보 없이 스냅샷만 저장 |

회신은 **원 요청 메시지에 인용 답장**이다. 티켓 본문에 `[요청출처]` 좌표를 남겨
어느 대화방 어느 메시지에 답할지 찾는다. 좌표가 없는 업무(사람이 직접 만든 것)는
통보 대상에서 제외된다.

## 7. 미해결·리스크

### 7.1 🔴 CRM API 스펙 미확정

기획서도 *"단건 조회 API 연동 (Method: GET)"*까지만 정하고 있다.
엔드포인트·인증·응답 필드명이 필요하다. **CRM 트랙의 유일한 블로커.**

### 7.2 🔴 마스킹 정책 (유보)

기획서 §5 화면 예시는 고객 담당자 이메일·전화를 마스킹 없이 노출하는데,
§1 리스크에는 인프라보안팀의 *"플랫폼 접목 원천 차단 원칙 고수"*가 명시되어 있다.

**PoC 결정**: 원안대로 노출. 리스크는 추후 협의.
운영 전환 전 반드시 재검토. `CRM_MASK=1`로 코드 수정 없이 되돌릴 수 있다.

### 7.3 🔴 자체 구현 방식 고유 리스크

- 개인 액세스 토큰은 **본인과 동일 권한**(메일·드라이브·프로젝트 포함).
  봇 전용으로 격리 불가
- 티켓 작성자·메시지 발신자가 **봇이 아니라 본인 이름**으로 표시
- 참여 중인 **모든 대화방** 메시지가 유입 (화이트리스트로 대응 중)
- 정식 기능 경로가 아니므로 **운영 투입 전 내부 승인** 필요

→ **봇 전용 계정을 발급받으면 위 넷이 동시에 해소된다.** 우선순위 높은 후속 과제.

### 7.4 LLM 외부 전송

Claude Haiku 4.5는 외부 API다. 고객사명·담당자 연락처가 사외로 나간다.
Dooray AI의 가드레일(DLP·인젝션 탐지)도 적용되지 않는다(`01` §4).
마스킹 건과 함께 보안 협의 안건으로 묶어야 한다.

실측 비용: 건당 $0.00095, 1,000건 약 1,330원. 평균 지연 1.09초.

### 7.5 "현황판 = Dooray! News" 문구 불일치

기술지원 기획서는 현황판을 Dooray! News로 명시하나, News는 알림 피드이지
현황판이 아니다. 업무(Project) 보드로 구현했고 기능 요건은 충족하나
**인포Biz본부와 문구 합의가 필요하다.**

5. 메시지 최대 길이 / rate limit
6. 파일 **다운로드** 경로 (메타데이터 수신은 확인됨)
7. Dooray 플랫폼 감사로그 제공 범위
8. 위키 가이드 문서 현행화 요청 (샘플 코드가 동작하지 않음)
