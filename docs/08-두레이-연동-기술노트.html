두레이 연동 기술노트

AI 프리미엄 라이선스 없이 Dooray 봇을 만들며 알아낸 것. 전부 실제로 돌려보고 확인한 내용이며, 막혔던 자리를 그대로 남겼습니다.

대상 소켓 · 슬래시 커맨드 · 업무 API 코드 github.com/final5545/dooray-poc

결론부터

공식 Extension Agent는 AI 프리미엄 라이선스가 있어야 합니다. 그런데 필요가 없었습니다.

Dooray 소켓 모드의 인증은 에이전트 단위가 아니라 사람(멤버) 단위입니다. 개인 액세스 토큰으로 소켓을 열 수 있고, 그 순간부터 그 계정이 보는 모든 대화가 흘러들어옵니다.

라이선스 없이 되는 것

  • 메시지 수신 — 소켓 모드(아웃바운드)
  • 발신 · 인용 답장 — 메신저 API
  • 업무 등록 · 상태 변경 · 본문 수정
  • 슬래시 커맨드와 버튼 — 연동 서비스 앱
  • 봇 이름으로 발신 — 호출 맥락 안에서
  • 내 Dooray! News 알림
  • 남에게 개인 알림 — 1:1 대화방

못 넘은 것

  • 남의 Dooray! News에 쓰기 — 그 채널의 멤버가 아님. 시스템 봇 권한이 필요합니다
  • 아무 때나 먼저 말 거는 봇 — 토큰이 호출마다 발급됨
  • 일반 메시지의 버튼 클릭 — 어느 앱 것인지 Dooray가 모름
  • 여러 줄 슬래시 커맨드 — 개행이 들어가면 일반 메시지가 됨
  • 상태 변경 자동 알림 — Dooray가 보내지 않음

못 넘은 것은 사실상 첫 줄 하나뿐이고, 그마저 1:1 대화방으로 대체됩니다. 나머지 넷은 우회 설계로 모두 해결했습니다.

01소켓 붙기 — 토큰이 전부다

POST https://api.dooray.com/common/v1/socket-mode/tokens
     Authorization: dooray-api {개인 액세스 토큰}
     {}                                          ← 본문은 빈 객체

→ { accessToken, tenantId, organizationMemberId }

WebSocket
wss://{테넌트}/messenger/v5/ws/{tenantId}/{organizationMemberId}
     Authorization: Bearer {accessToken}

organizationMemberId는 내 멤버 ID입니다. 뒤에서 계속 쓰입니다.

수명이 1시간 — 만료 전에 스스로 끊어야 한다

accessToken은 JWT입니다. SDK는 연결이 끊긴 뒤에야 재발급하는데, 그러면 만료 순간부터 재연결까지 메시지를 놓칩니다. JWT의 exp를 직접 읽어 만료 2분 전에 우리가 먼저 끊었습니다.

payload = accessToken.split(".")[1]
payload += "=" * (-len(payload) % 4)          # base64 패딩 복원
exp = json.loads(base64.urlsafe_b64decode(payload))["exp"]
ttl = max(exp - time.time() - 120, 60)

한 토큰에 소켓 하나

같은 토큰으로 두 번째 소켓을 열면 1008 AGENT_ALREADY_CONNECTED로 거절당합니다. 재연결 간격을 종료 사유별로 달리해야 합니다. 구분하지 않으면 1008을 맞고 즉시 재시도하는 뜨거운 루프에 빠집니다.

종료 사유재연결
토큰 갱신 (계획된 종료)즉시
1008 중복 접속15초 대기
그 외지수 백오프

02프레임 읽기 — 내가 보낸 걸 내가 받는다

개인 계정 소켓이라 우리가 API로 보낸 응답도 우리에게 되돌아옵니다. 그대로 두면 무한 루프입니다. 그렇다고 "내가 보낸 것"을 전부 거르면 내가 친 명령도 못 받습니다.

화이트리스트가 필수입니다. 소켓에는 초대 개념이 없어 그 계정이 참여 중인 모든 대화방이 흘러들어옵니다(우리 계정은 250개). 처리할 채널을 명시하지 않으면 전 대화 내용이 로그에 쏟아집니다.

03Dooray! News의 정체

News는 개인 봇 채널이고, 채널 ID가 그 사람의 memberId와 같습니다. 일반 대화방 목록에는 나오지 않습니다.

발신 대상결과이유
내 News200내가 그 채널의 멤버
남의 News500CHANNEL_NOT_JOINED_MEMBER_ERROR
남과의 1:1 대화방200둘 다 참여 중

Dooray-Bot이 모두의 News에 쓰는 것은 시스템 봇 권한이라 개인 토큰으로는 흉내 낼 수 없습니다. 우회로가 아니라 권한의 벽입니다. 그래서 본인이면 News, 남이면 1:1로 갈라 보냅니다.

04알림 규칙 — 기획서 전제가 틀렸다

기획서는 "완료되면 알림이 간다"를 전제하고 있었는데, 여러 조합을 만들어 확인해 보니 그렇지 않았습니다.

사건알림
업무 등록간다
담당자·참조자 추가간다
상태 변경 (접수 → 완료)안 간다
내가 한 행동나에게는 안 온다
내가 작성자인 업무나에게는 안 온다
작성자는 참조자가 될 수 없습니다. 봇이 작성자인 구조에서 요청자를 참조자로 넣으면 users.cc가 빈 배열로 돌아옵니다. 오류도 없이 조용히 무시됩니다.

상태 변경에 알림이 없으므로 완료 감지는 폴링입니다. 스냅샷 비교 방식이라 주기는 지연 시간만 결정하고 누락 여부는 결정하지 않습니다. 단, 생성 직후 첫 폴링 전에 완료되면 "처음 보는데 이미 완료"로 판단해 누락되므로, 티켓을 만든 즉시 스냅샷에 등록해야 합니다.

05슬래시 커맨드 — 버튼을 쓰려면

등록 경로 (찾기 어려웠다)

메신저 → 좌측 상단 내 이름 → 슬래시 커맨드 연동. 개인 설정이나 관리자 화면이 아니라 메신저 안에 있습니다. Request URL(커맨드)과 Interactive Message Request URL(버튼 클릭) 둘 다 넣어야 하고, 대화방에 커맨드를 추가하는 단계를 빠뜨리면 보이지 않습니다.

토큰 두 개를 헷갈리지 말 것

필드정체쓰임
appToken앱 설정 화면의 고정값요청이 진짜인지 검증만
cmdToken호출마다 새로 발급responseUrl에 이미 박혀 있음

appToken으로 hook URL을 만들어 쏘면 INTEGRATION_COMMAND_CALL_NOT_EXIST_ERROR로 거절당합니다. responseUrl로는 앱 이름(= 봇)으로 메시지를 보낼 수 있지만 그 호출 맥락 안에서만입니다. 버튼 클릭도 하나의 호출이므로, 클릭 시점에는 봇으로 말할 수 있습니다.

두 가지 결정적 제약

설계를 바꿔야 했던 지점입니다.

① 일반 메시지의 버튼은 죽어 있다

  • 메신저 API로 보낸 메시지에 actions를 넣으면 버튼이 그려지긴 합니다. 그런데 눌러도 아무 일이 없습니다.
  • 진짜 업무를 바꾸는 값을 실어 눌러도 상태가 그대로였습니다.
  • 개인 토큰으로 보낸 메시지의 버튼이 어느 앱 것인지 Dooray가 알 방법이 없기 때문입니다.

② 여러 줄 커맨드는 커맨드가 아니다

  • /커맨드 뒤에 Shift+Enter로 개행하면 일반 메시지로 전송됩니다.
  • 여러 줄 양식을 커맨드 인자로 넘길 수 없습니다.
  • 우회 — 양식은 일반 메시지로 올리고, 커맨드가 GET /channels/{id}/logs로 방의 로그에서 그 사람의 마지막 양식을 찾아 읽습니다.
버튼이 실제로 동작하는 곳은 슬래시 커맨드 응답뿐입니다. 버튼이 필요하면 처음부터 슬래시 커맨드로 설계하세요. 일반 메시지에 버튼을 달았다가 갈아엎게 됩니다.

06업무 API — 세 가지만 알면 된다

  1. 목록 응답에 필요한 게 다 들어 있습니다. GET /posts 한 건에 id · number · subject · workflowClass가 모두 있어 건별 조회(N+1)가 불필요합니다. 우리도 걷어내고 나서 응답이 0.6초로 떨어졌습니다.
  2. 워크플로는 이름이 아니라 class로 찾아야 합니다. 상태 이름은 프로젝트마다 다릅니다(할 일/등록). registered · working · closed로 찾으세요.
  3. 업무에 임의 필드를 붙일 수 없습니다. 완료 알림을 받았을 때 "어느 대화방 어느 메시지에 답할지"를 담을 곳이 없어 본문에 한 줄로 남겼습니다.
[요청출처] channel={채널ID} message={메시지ID} requester={요청자ID}

삭제 API는 없습니다 — DELETE /posts/{id}는 404입니다. 화면에서 지워야 합니다.

07인바운드 — Dooray가 우리를 호출한다

소켓은 아웃바운드입니다. 우리가 붙습니다. 그런데 슬래시 커맨드와 버튼은 Dooray가 우리 서버를 호출합니다. 공개 접근 가능한 HTTPS URL이 필요합니다.

ngrok은 사내망에서 안 됩니다. Fortinet TLS 가로채기 때문에 터널 자체가 403으로 막히고, 터널에 도달한 요청이 0건이었습니다. 대신 ai-node에 공인 IP와 Traefik, Let's Encrypt, 와일드카드 DNS가 이미 있어 새 서버도 DNS 작업도 필요 없었습니다.

다음에 이걸 하는 사람에게

  1. 소켓부터 열어 보세요. 개인 액세스 토큰 하나로 5분이면 됩니다. 여기가 되면 나머지는 다 됩니다.
  2. content.token을 먼저 이해하세요. 루프 방지의 핵심이고, 모르면 무한 루프를 겪고 나서야 알게 됩니다.
  3. 화이트리스트를 먼저 거세요. 안 그러면 전 대화방이 로그에 쏟아집니다.
  4. 버튼이 필요하면 처음부터 슬래시 커맨드로 설계하세요.
  5. 알림을 기대하지 마세요. 상태 변경에는 알림이 없습니다. 폴링이거나, 버튼으로 바꿔 클릭을 곧 이벤트로 삼거나 둘 중 하나입니다.
