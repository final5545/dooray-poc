01자연어 요청 + 1회 확인

지난 회의 — "현재의 해시·슬래시 명령과 다단계 양식은 사용성이 떨어지므로 자연어 요청과 1회 확인 중심으로 단순화"

지적대로 명령이 17종이었고, 양식 경로는 입력이 세 번 필요했습니다.

02사내 CRM 실 API 연결

지난 회의 — "CRM 개발서버와 실제 API가 연결되지 않아 실데이터 조회·양방향 상태동기화는 검증하지 못함"

고객정보 조회 API를 받아 연결했습니다. 응답 40ms로 실사용에 문제가 없습니다.

확인된 제약 — 필드 절반이 없습니다

기획서 §4가 요구한 항목 중 계약정보 전부와 설치정보 대부분, 이메일이 응답에 없습니다.

섹션기획서 요구실 API
기본정보고객번호 · 구분 · 고객명 · 기기전부 있음
사용자정보부서 · 이름 · 전화1 · 전화2 · 이메일전화2 · 이메일 없음
계약정보청구일 · 계약시작 · 종료 · 갱신전부 없음
설치정보설치일자 · 회선구분 · 통신사전부 없음
(신규)—주소 · 비고

값이 없는 게 아니라 응답에 항목 자체가 없어서, 빈 칸으로 늘어놓으면 "계약이 없는 고객"으로 오해됩니다. 지금은 해당 섹션을 통째로 생략해 보여줍니다.

확인이 필요합니다. 계약·설치정보를 화면에 넣으려면 API에 필드를 추가해야 합니다. 기술지원 담당자가 계약 종료일을 보고 판단하는 경우가 있다면 필요한 항목입니다.

보고 사항 — 빈 조회에 전체 목록이 반환됩니다

경계 동작을 확인하다 발견했습니다.

잘못된 요청인데 데이터가 딸려 옵니다. 저희 쪽에서는 빈 조회를 보내지 않도록 막았지만, API 자체에서도 막는 편이 안전합니다. (건수만 확인했고 내용은 열지 않았습니다.)

망 접근

사무망(개발 PC)에서는 닿습니다. 서버망(ai-node)에서는 닿지 않습니다. 현재는 조회·요청 기능이 개발 PC에서 돌고 있어 동작에 지장이 없지만, 운영 전환 시에는 방화벽 허용이 필요합니다.

03아직 하지 않은 것

지난 회의 — "승인 사용자·전용 채널 화이트리스트, 최소 필드 전송, 호출속도 제한, 감사로그와 별도 제어계층을 기본조건으로 검토"

기본조건으로 제시된 다섯 중 채널 화이트리스트만 되어 있습니다.

항목상태
전용 채널 화이트리스트있음지정한 대화방 외에는 본문을 로그에도 남기지 않음
승인 사용자 화이트리스트없음채널에 들어온 사람이면 누구나 사용 가능
최소 필드 전송없음마스킹 스위치는 있으나 기본 꺼짐 (PoC 결정)
호출속도 제한없음CRM·LLM 호출에 제한 없음
감사로그없음일반 운영 로그만. 누가 무엇을 조회했는지 별도 기록 없음
PoC 단계의 의도된 상태입니다. 다만 실 고객 데이터가 연결된 지금부터는 성격이 달라집니다. 시연·검증 범위를 넘어 실사용을 시작하기 전에 위 항목들을 갖춰야 합니다. 특히 승인 사용자 제한과 감사로그는 실데이터를 다루는 이상 우선순위가 높습니다.

그 밖에

  • 양방향 상태 동기화 — Dooray 업무 상태 변경은 되지만 CRM 쪽과 맞추는 것은 미착수. 업무 API 스펙 확인 후
  • Dooray 라이선스·약관, 개인토큰 사용범위 — 확인되지 않음. 현재 개인 액세스 토큰으로 동작하며, 이는 토큰 소유자와 동일한 권한입니다

결정을 청하는 사항

  1. CRM API 필드 추가 — 계약정보·설치정보를 화면에 넣을 것인지. 넣는다면 API에 필드 추가가 필요합니다.
  2. 업무관리 위치 — Dooray 프로젝트에 둘지, CRM으로 옮길지. 「Dooray는 요청 인터페이스, CRM은 원장」 방향에는 동의합니다. 다만 CRM 업무 API가 저희가 쓰는 여덟 가지 동작을 지원해야 성립합니다. 확인 항목을 별도 문서로 정리했습니다.
  3. 실사용 시작 시점과 보안 요건 — 위 §3의 항목 중 어디까지를 선행 조건으로 볼지. 특히 승인 사용자 제한과 감사로그.
  4. 서버망 → CRM 방화벽 — 운영 전환 시 필요합니다. 지금은 개발 PC에서 돌고 있어 급하지 않습니다.
다음 단계 제안. CRM 업무 API 스펙을 받는 것이 가장 앞섭니다 — 그것이 정해져야 원장 구조도, 상태 동기화도, 2차 시나리오도 설계할 수 있습니다. 그동안 저희는 보안 항목(승인 사용자·감사로그)을 먼저 채우겠습니다. 실데이터가 연결된 이상 그쪽이 먼저입니다.
